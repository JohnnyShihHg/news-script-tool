# 協作工具守門員（使用者腳本）

擋住協作工具（小幫手）的三個毛病。**只讀不改文件內容**——不輸入、不刪除、不格式化，
只戳同步、限流一個會閃的渲染函式、攔住把你拉走的捲動。

| 症狀 | 這支做了什麼 |
|---|---|
| 改動卡在自己電腦、別台看不到，要按 F5 才同步 | 每 10 秒補送一次，不等你想到按 F5 |
| 卡住的時候畫面完全看不出來 | 卡住就整頁紅框 + 右下角狀態面板 |
| 重複行的螢光一直閃 | 把它限流成最多每 1.5 秒重畫一次 |
| 打完字往下捲，畫面自己跳回去 | 攔下程式造成的捲動；你自己捲的、打字時跳到游標的都照常 |

## 為什麼要這支（問題在哪）

協作工具的同步**沒有 WebSocket**，是 HTTP 輪詢（拉 850ms 一次、推 180ms 防抖）。
問題出在上傳那一側：

```js
serverSyncState.pendingUpdates.push(update);
if (serverSyncState.bootstrapFinalized) {   // ← 閘門
  scheduleServerSyncFlush();
}
```

旗標沒亮，改動就只是堆在記憶體裡，**沒有任何東西會再去推它**——沒有重試、沒有定時器。
那一頁變成只收不發，而且外觀完全正常。旗標要亮需要「IndexedDB 載入完成」**且**「某次
輪詢回報沒有更多資料」兩件事同時成立，其中一件沒達成就永遠卡著。

它另外有一條**不看那道閘門**的「離開前補送」，掛在 window 的 `pagehide` 上——這就是
「最後編輯者刷新一次，別人才看得到」的原因。這支腳本做的就是定期替你觸發那條路。

## 安裝

1. Chrome 裝 [Tampermonkey](https://chromewebstore.google.com/detail/tampermonkey/dhdgffkkebhmkfjojejmpbldmpobfkfo)
2. Tampermonkey → 新增腳本 → 把 `collab-guard.user.js` 的內容整段貼上 → 存檔
3. 重新整理協作工具那一頁，右下角出現「守門員」小面板就是裝好了

**為什麼不是書籤？** 書籤一重載就沒了，而這支要常駐（自動重載自救那條更是會把自己
載掉）。查標記那支維持書籤沒問題，因為那是點一下用完就收。

## 設定

腳本開頭的 `CONFIG`：

| 項目 | 預設 | 說明 |
|---|---|---|
| `pushEverySeconds` | 10 | 多久補送一次。沒有東西要推就什麼都不送，調短沒副作用 |
| `highlightMinGapMs` | 1500 | 重複行螢光最快多久重畫一次。調大更不閃、標記更新更慢 |
| `scrollGuardMs` | 1200 | 使用者停止捲動後，多久內的程式捲動視為「被拉走」 |
| `scrollGuardMinJumpPx` | 80 | 跳超過這個距離才攔，小幅調整不管 |
| `autoReloadAfterStuckSeconds` | 0（關閉） | 設成 120 = 卡住兩分鐘且你沒在打字就自動重載 |
| `debugScroll` | false | 開了會在 console 印出每次被擋的捲動**來源堆疊** |

### 自動重載值不值得開

積壓超過 48,000 字元時，「離開前補送」會**靜默放棄**（它沒有分塊，雖然同一支程式裡
就有現成的分塊函式）。這時候只剩「重載後 bootstrap 的分塊推送」救得回來。所以：
平常靠補送不讓它累積，真的卡死就靠重載。會打斷你的編輯，所以預設關閉。

### 找出捲動跳動的真兇

頁面裡有十幾處會改 `scrollTop`，Quill 自己在遠端更新進來時也會動選取範圍，所以這支
是**攔結果**而不是修源頭。想知道到底是誰幹的：把 `debugScroll` 改成 `true`，重現一次
跳動，看 console 裡的堆疊。

## 做法與限制

- **推送**：`window.dispatchEvent(new Event("pagehide"))`。那個監聽器不檢查事件是不是
  真的來自瀏覽器。推的是「伺服器還缺的部分」，沒缺就不送，所以多戳沒有副作用
- **螢光限流**：包住 `requestAnimationFrame`，認 `callback.name === "renderDuplicateLineHighlights"`。
  **依賴函式名字**——作者哪天改名或上壓縮，這段會自動失效（變成沒效果，不會壞）
- **捲動防跳**：接管捲動容器的 `scrollTop` 設定子。使用者用滾輪、觸控、拖捲軸捲動
  **不會**經過設定子，只有程式指派才會，所以分得乾淨。另外也擋編輯區內的
  `scrollIntoView`
- **沒辦法做的**：把收到的更新塞進頁面的 Y.Doc（接收端卡住只能靠重載）、解除瀏覽器
  對背景分頁的計時器節流、改掉那個 48KB 上限

## 測過什麼

在 `tools/collab-guard/` 的假頁面上實測三件事（真頁面不能拿來試，一碰所有人都會看到）：

| 測項 | 結果 |
|---|---|
| 連續排 10 次螢光重畫 | 只跑 1 次 |
| 使用者捲到 1200 後程式跳回 0 | 停在 1200，擋下 |
| 打字中程式捲到 500 | 放行（跳到游標是正常行為） |

第一版的捲動防跳是用「距離上次使用者捲動幾毫秒」來猜，**實測直接失敗**：程式的跳動
正好發生在使用者剛捲完那一瞬間，被誤判成使用者自己捲的。才改成接管設定子。
