# 協作工具守門員（使用者腳本）

擋住協作工具（小幫手）的三個毛病。**只讀不改文件內容**——不輸入、不刪除、不格式化，
只戳同步、限流一個會閃的渲染函式、攔住把你拉走的捲動。

| 症狀 | 這支做了什麼 |
|---|---|
| 新開分頁一直停在「正在載入共同文章」，要手動重新整理才讀得完 | 開頁 20 秒還在載入、而且你沒打字，就自動重整一次（一個分頁只重整一次） |
| 改動卡在自己電腦、別台看不到，要按 F5 才同步 | 每 10 秒補送一次，不等你想到按 F5 |
| 卡住的時候畫面完全看不出來 | 卡住就整頁紅框 + 右下角狀態面板 |
| 重複行的螢光一直閃 | 把它限流成最多每 1.5 秒重畫一次 |
| 打完字往下捲，畫面自己跳回去 | 攔下程式造成的捲動；你自己捲的、打字時跳到游標的都照常 |
| 行的「複製」按鈕壓在文字上 | 按鈕縮小讓它塞得進左邊空白；還是塞不下就淡化，滑鼠移上去才變清楚 |
| 「文件分頁」漢堡按了沒反應 | 補上收合後的欄寬（他的 CSS 把收合跟展開寫成一樣的值） |

## 為什麼要這支（問題在哪）

協作工具的同步**沒有 WebSocket**，是 HTTP 輪詢（拉 850ms 一次、推 180ms 防抖）。
問題出在上傳那一側：

```js
serverSyncState.pendingUpdates.push(update);
if (serverSyncState.bootstrapFinalized) {   // ← 閘門
  scheduleServerSyncFlush();
}
```

旗標沒亮，改動就只是堆在記憶體裡，**沒有任何東西會再去推它**——沒有重試、沒有定時器。
那一頁變成只收不發，而且外觀完全正常。旗標要亮需要「IndexedDB 載入完成」**且**「某次
輪詢回報沒有更多資料」兩件事同時成立，其中一件沒達成就永遠卡著。

它另外有一條**不看那道閘門**的「離開前補送」，掛在 window 的 `pagehide` 上——這就是
「最後編輯者刷新一次，別人才看得到」的原因。這支腳本做的就是定期替你觸發那條路。

## 安裝

先裝 [Tampermonkey](https://chromewebstore.google.com/detail/tampermonkey/dhdgffkkebhmkfjojejmpbldmpobfkfo)，然後選一種：

**從網址安裝（推薦，發給同事就發這一行）**

```
https://raw.githubusercontent.com/JohnnyShihHg/news-script-tool/main/tools/collab-guard/collab-guard.user.js
```

貼進網址列按 Enter，Tampermonkey 會跳出安裝頁。這條路**有自動更新**。

**貼上安裝**

Tampermonkey → 新增腳本 → **全選範本**、把 `collab-guard.user.js` 整段**貼上蓋掉** → 存檔。

⚠ 一定要蓋掉不要接在後面：範本自帶一段 `// ==UserScript==` 標頭，兩段並存腳本不會生效，
而且不會報錯——這是「裝了沒反應」最常見的原因。

裝好後**重新整理協作工具那一頁**（裝之前就開著的分頁不會回溯注入），右下角出現
「守門員」小面板就是生效了。竄改猴管理面板的「上次執行」還是空的，代表網址比對沒
對上——把完整網址貼出來改 `@match`。

比對寫成整個 `*.chatgpt.site`，要不要啟動改由「這一頁有沒有 Quill 編輯器」決定（最多
等 20 秒）。綁死 `/helper4` 這個路徑的話，網址只要多一層或帶別的路徑就整支不執行，
而且在竄改猴裡只顯示「尚未執行過」，看不出原因。沒有編輯器的頁面它會安靜退出。

## 改了程式要記得加版本號

`@updateURL` / `@downloadURL` 指到 repo 的 raw 網址，Tampermonkey 會定期比對 `@version`。
**改完一定要把 `@version` 往上加**，否則大家手上永遠是舊的——它只看版本號，不看內容。

**為什麼不是書籤？** 書籤一重載就沒了，而這支要常駐（自動重載自救那條更是會把自己
載掉）。查標記那支維持書籤沒問題，因為那是點一下用完就收。

## 設定

腳本開頭的 `CONFIG`：

| 項目 | 預設 | 說明 |
|---|---|---|
| `pushEverySeconds` | 10 | 多久補送一次。沒有東西要推就什麼都不送，調短沒副作用 |
| `highlightMinGapMs` | 1500 | 重複行螢光最快多久重畫一次。調大更不閃、標記更新更慢 |
| `scrollGuardMs` | 1200 | 使用者停止捲動後，多久內的程式捲動視為「被拉走」 |
| `scrollGuardMinJumpPx` | 80 | 跳超過這個距離才攔，小幅調整不管 |
| `coldStartReloadSeconds` | 20 | 新開分頁超過這麼久還在「正在載入共同文章」就自動重整一次；0 = 關閉 |
| `autoReloadAfterStuckSeconds` | 0（關閉） | 設成 120 = 卡住兩分鐘且你沒在打字就自動重載 |
| `reloadCooldownMinutes` | 5 | 兩次自動重載至少間隔這麼久 |
| `showHud` | false | 右下角狀態小框。關掉仍然會紅框示警 |
| `compactLineButtons` | true | 行動作按鈕縮小 |
| `keepLineButtonsOffText` | true | 動作列蓋到文字時往左挪 |
| `fixOutlineCollapse` | true | 修漢堡收合 |
| `debugScroll` | false | 開了會在 console 印出每次被擋的捲動**來源堆疊** |

### 版面修正的細節

**漢堡收合**：他的 CSS 把收合後的欄寬寫成跟展開時一模一樣

```css
.main                   { grid-template-columns: 220px minmax(0,1fr) clamp(235px,20vw,250px) }
.main.outline-collapsed { grid-template-columns: 220px minmax(0,1fr) clamp(235px,20vw,250px) }
```

所以按漢堡只會把標題和清單 `display:none`，那 220px 的空欄還杵在那裡 —— 看起來就像
按了沒反應。右邊快捷面板的收合有把欄寬改成 42px，所以是好的。兩邊的面板可以各自收合，所以**四種組合都要寫**。在真實頁面上量過（只改本機顯示，
測完還原）：

| 狀態 | 欄寬 | 編輯區 |
|---|---|---|
| 兩邊展開 | `220 / 569 / 235` | 569px |
| 只左收 | `42 / 747 / 235` | 747px |
| 只右收 | `220 / 762 / 42` | 762px |
| 兩邊都收 | `42 / 940 / 42` | **940px** |

第一版只寫了「左邊收合」一種，而且把第三欄寫死成展開寬度——**兩邊同時收合時右邊
會被蓋回去縮不了**。三個 class 的選擇器比兩個 class 的更具體，組合那條才會贏。

另外欄寬縮到 42px 之後，他原本的內距（左右各 10px＋標題列 4px）只剩 14px，塞不下
30px 的漢堡按鈕，所以照他右邊面板的做法把內距縮小、按鈕置中。

**行動作按鈕**：他的程式會先試著把動作列放在文字左邊，空間不夠時退而求其次貼在可視
區左緣 —— 就壓在文字上了，放大檢視時特別容易發生（左邊空白變窄）。

他另外有一條分支：**「文件分頁收合時，就把動作列停進那一欄裡」**，可用寬度算成
`欄寬 - 8*2`。修好漢堡之後那一欄真的縮到 42px，可用寬度只剩 26px，於是動作列被
壓成 26px 又加上 `wrap` 變多行，整個咬在最左邊 —— 這是修好一個 bug 之後才浮出來的
第二個 bug。

所以這裡做三件事：按鈕縮小讓它塞得進左邊留白；把他的擠壓解掉（移除 `wrap`、清掉
寫死的寬度）；位置一律貼齊文字左緣，讓它離你正在看的那一行夠近。真的沒有空間時
（放大到左邊幾乎沒有留白）淡化到 0.35，滑鼠移上去恢復。

### 冷啟動自動重整（1.1.0）

新開的分頁要把整份共同文章讀下來，常常停在「正在載入共同文章」不動，手動重新整理一次
（重跑一次載入流程）就好。所以開頁後 `coldStartReloadSeconds`（20 秒）還在載入、而且
這段時間沒有打字，就自動重整一次。冷啟動時還沒有任何編輯，不會掉資料。

- **一個分頁只自動重整一次**：重整後還是卡住就不再重整（紅框照樣提示），避免本來就讀
  很久的環境被一直重整。記號存兩份（`sessionStorage` 和 `window.name`），10 分鐘內有效；網站儲存被
  封鎖時靠 `window.name`，不會變成每 20 秒重整一次。
- 這一段不等編輯器出現就開始看（卡住時編輯器可能根本還沒出來）。只認協作工具才有的
  「正在載入共同文章」；30 秒內都沒看到狀態文字就當作不是協作工具，停止。
- **量測**：每次讀完花幾秒記在 `localStorage` 的 `collabGuardColdLoads`（最近 20 筆，
  有沒有自動重整也記），HUD 也會顯示。在 console 打
  `JSON.parse(localStorage.collabGuardColdLoads)` 就看得到，用來調整秒數。
- 測試頁：`tests/fake-cold.html?mode=stuck`（一直載入中，應該剛好重整一次）、
  `?mode=ok`（3 秒讀完，不重整，記一筆約 3 秒）。加上 `&nostorage=1` 模擬儲存被封鎖，一樣應該只重整一次。

### 快取診斷（1.1.0，只讀）

懷疑冷啟動慢是協作工具的本地快取（IndexedDB）沒寫好、每次開頁都從頭讀。讀完 30 秒後，
守門員**只數**這個網站有哪些 IndexedDB、每個物件庫幾筆、網站用了多少儲存空間，**不讀
任何內容**（文件裡有未播出的稿）。結果記在 `localStorage` 的 `collabGuardCacheInfo`，
HUD 顯示摘要；console 打 `collabGuardDiag()` 可以再跑一次。打開的連線數完馬上關，頁面
要升級資料庫時也立刻讓開。

用來判斷要不要做「每 15 分鐘寫一次快取」：開頁讀取很慢的那台，快取是不是幾乎是空的、
或筆數一直很大（沒有合併）。在 console 打：

```js
JSON.parse(localStorage.collabGuardColdLoads)   // 每次開頁讀了幾秒、有沒有自動重整
JSON.parse(localStorage.collabGuardCacheInfo)   // 快取有幾個資料庫、幾筆
```

### 自動重載值不值得開

積壓超過 48,000 字元時，「離開前補送」會**靜默放棄**（它沒有分塊，雖然同一支程式裡
就有現成的分塊函式）。這時候只剩「重載後 bootstrap 的分塊推送」救得回來。所以：
平常靠補送不讓它累積，真的卡死就靠重載。會打斷你的編輯，所以預設關閉。

### 找出捲動跳動的真兇

頁面裡有十幾處會改 `scrollTop`，Quill 自己在遠端更新進來時也會動選取範圍，所以這支
是**攔結果**而不是修源頭。想知道到底是誰幹的：把 `debugScroll` 改成 `true`，重現一次
跳動，看 console 裡的堆疊。

## 做法與限制

- **推送**：`window.dispatchEvent(new Event("pagehide"))`。那個監聽器不檢查事件是不是
  真的來自瀏覽器。推的是「伺服器還缺的部分」，沒缺就不送，所以多戳沒有副作用
- **螢光限流**：包住 `requestAnimationFrame`，認 `callback.name === "renderDuplicateLineHighlights"`。
  **依賴函式名字**——作者哪天改名或上壓縮，這段會自動失效（變成沒效果，不會壞）
- **捲動防跳**：接管捲動容器的 `scrollTop` 設定子。使用者用滾輪、觸控、拖捲軸捲動
  **不會**經過設定子，只有程式指派才會，所以分得乾淨。另外也擋編輯區內的
  `scrollIntoView`
- **但「使用者按按鈕要它捲」不能擋**。點在按鈕、連結、輸入框、分頁清單上，或按
  Home/End/快捷鍵，都會替接下來 1.2 秒的程式捲動開綠燈；點在別處（拖捲軸、點編輯區）
  才算自己捲。使用者一旦自己捲動，綠燈立刻取消 —— 否則「打完字往下捲被拉回去」會在
  那個空窗期復活。方向鍵、PageUp/Down、空白鍵算「自己捲」而**不算打字**，不然打字
  豁免會把方向鍵之後的跳動一起放過去
- **沒辦法做的**：把收到的更新塞進頁面的 Y.Doc（接收端卡住只能靠重載）、解除瀏覽器
  對背景分頁的計時器節流、改掉那個 48KB 上限

## 測過什麼

在 `tools/collab-guard/` 的假頁面上實測三件事（真頁面不能拿來試，一碰所有人都會看到）：

| 測項 | 結果 |
|---|---|
| 連續排 10 次螢光重畫 | 只跑 1 次 |
| 使用者捲到 1200 後程式跳回 0 | 停在 1200，擋下 |
| 打字中程式捲到 500 | 放行（跳到游標是正常行為） |
| 動作列被壓進收合後的分頁欄（26px 寬、wrap 多行、貼最左） | 回到自然寬 38px、取消 wrap、貼齊文字左緣 x=54 |
| 動作列被放在文字上（x=100，文字從 98 開始） | 挪到 x=54，右緣 92，不再重疊 |
| 左邊完全沒空間（文字從 x=8 開始） | 透明度降到 0.35，滑鼠移上去變 1 |
| 漢堡收合（**在真實頁面上量的**） | 欄寬 220px → 42px，編輯區 569px → 747px |
| 點「找下一個重複」這類會捲動的按鈕 | 捲得過去（1.0.4 以前被防跳擋死） |
| 點完按鈕後自己再捲一下，接著遠端跳動 | 擋下（綠燈已被取消） |
| 打字時程式捲到游標 | 放行 |
| 方向鍵捲動後的遠端跳動 | 擋下 |
| Home 鍵 | 捲得過去 |

第一版的捲動防跳是用「距離上次使用者捲動幾毫秒」來猜，**實測直接失敗**：程式的跳動
正好發生在使用者剛捲完那一瞬間，被誤判成使用者自己捲的。才改成接管設定子。
